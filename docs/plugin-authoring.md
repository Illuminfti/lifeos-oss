# Authoring a capture plugin

LifeOS plugins are provider adapters, not miniature LifeOS forks. They own provider authentication, pagination, cursor semantics, normalization, and sanitized health. They emit `CaptureEvent v1` and never write canon.

## Package registration

Register a Python entry point named with the public connector key:

```toml
[project.entry-points."lifeos.connectors"]
acme-notes = "lifeos_acme.plugin:Plugin"
```

Core discovers the entry point at runtime. No edit to the LifeOS registry or ingest code is required.

## Minimum implementation

```python
from lifeos.connectors.base import BasePlugin
from lifeos.contracts import (
    ConnectionReceipt,
    ConnectorManifest,
    HealthReport,
    SyncBatch,
)


class Plugin(BasePlugin):
    def __init__(self, context=None):
        super().__init__(context)
        self.manifest = ConnectorManifest(
            id="org.example.acme-notes",
            display_name="Acme Notes",
            source_classes=["document"],
            capabilities=["backfill", "incremental_sync", "revoke", "purge"],
            auth_modes=["oauth2"],
            outbound_actions=False,
        )

    def connect(self, request) -> ConnectionReceipt:
        ...

    def backfill(self, request) -> SyncBatch:
        ...

    def sync(self, request) -> SyncBatch:
        ...

    def health(self, request=None) -> HealthReport:
        ...
```

A manifest declaring `outbound_actions=true` is rejected.

## Requests and context

The connector receives a `ConnectorContext` containing:

- `brain`: canonical brain path, when running under a local installation
- `queue`: durable ingest and webhook inbox
- `secrets`: resolver for `env:` and `file:` handles
- `http`: injectable HTTP transport used by tests

`connect()` receives a `secret_ref` plus public config. Persist the secret reference through `ConnectorManager`; never return a token in a receipt.

Backfill and sync receive:

```json
{
  "connection": {
    "connection_id": "con_...",
    "connector_key": "acme-notes",
    "public_config": {}
  },
  "secret_ref": "env:ACME_SECRET",
  "config": {},
  "checkpoint": {}
}
```

## Event rules

Every source record must have:

- a provider-stable `source_record_id`
- a meaningful `source_revision` or deterministic revision hash
- source occurrence time and LifeOS observation time
- a deterministic content hash generated by `CaptureEvent.build()`
- provider-neutral kind and actors
- attachment references rather than credentials or opaque live sessions

Updates reuse `source_record_id` and change `source_revision`. Deletions emit a tombstone event with `deleted=true`. Never silently omit a provider deletion that the provider exposes.

## Checkpoint rules

- Backfill and sync return the candidate next checkpoint in `SyncBatch`.
- LifeOS commits it only after every event in the batch is durably accepted.
- A repeated page or webhook must be safe to replay.
- Expired provider cursors raise a typed full-resync failure.
- A configured page cap sets `complete=false` and emits a warning.

## Webhooks

Signed webhook plugins verify the exact raw request body before enqueueing it. Provider callbacks first enter `webhook_inbox`; normalization happens during `sync()`. Put processed webhook IDs in `_ack_webhooks` inside the returned checkpoint. Core acknowledges them only after normalized events enter the ingest queue.

## Conformance tests

A third-party plugin should test:

1. manifest validation and `outbound_actions=false`
2. connect failure without credentials
3. no secret values in receipts, logs, events, or health
4. resumable backfill
5. replay-safe sync
6. update and deletion mapping
7. expired authorization and cursor behavior
8. rate-limit recovery
9. malformed payload quarantine or typed failure
10. revoke and purge
11. restart from persisted checkpoint
12. fixture transport without a live account

See the built-in `example` connector and repository tests.
